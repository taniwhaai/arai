**Outcome.** A developer can take a fresh repository, identify one rule that can block, exercise its allowed and denied cases, verify the selected host, and trace the decision to the same rule and source in the audit log. A team can repeat a subset of those checks on a pull request using its own GitHub configuration. Five minutes from an installed CLI to the first verified decision is a usability target to measure. Record installation and host sign-in time separately.

**Product boundary.** Arai owns local policy evaluation, repository CI, local diagnostics, capture preferences and open evidence formats. Kete owns device enrollment, identity and policy authority, organization approvals and exceptions, rollout, coverage across repositories, authenticated evidence ingestion, retention and reporting. Reuse the public Arai engine and preserve its embedding contract. The proposed Kete website copy is an editorial handoff to its owner after release. ## Architecture and contracts

**Structural tier** Small multi-module extension. Reuse three capabilities with different failure behavior: local evaluation must return a decision from a consistent policy snapshot; host setup must preserve other handlers and distinguish configuration from observed execution; evidence must handle missing correlation and protect captured data. Compose the existing CLI, host adapters and diff checker around those capabilities. These are ownership boundaries in the existing crate, not a request for three crates or a new service.

| Capability | Inputs and outputs | Effects and failure contract |
|---|---|---|
| Policy evaluation | Validated local sources plus canonical event/tool/action → matched rule references, effective severity, policy disposition and provenance | Scan atomically replaces the owned snapshot. Evaluation reuses normalized actions including each patch destination. Dry runs have no audit, host response or session-write effects. Invalid activation keeps the prior snapshot and returns a diagnostic. |
| Host setup and verification | Selected host, project, expected handler definition and available observations → registration, executable, invocation and probe results per host | Init updates only selected registrations, preserving neighbors and trust requirements. Static inspection never executes arbitrary commands found in config. Native proof requires a host-mediated action. Incomplete evidence remains explicitly unknown. |
| Decision evidence | Evaluation, host identity evidence, native call identity where supplied, capture settings → local event and aggregate views | One audit serialization boundary applies capture rules before hashing. Keep old JSONL byte-for-byte verifiable. Missing IDs or write receipts cannot substantiate an observed completion. Transport consumes the same local bucket format. |

**Shared vocabulary.** A rule reference contains a source identity, line, and optional authored rule ID. Preserve legacy numeric `triple_id` where available. Scope the authored ID to its project-root policy source. A policy disposition for PreToolUse is `deny`, `advise`, or `allow`. It describes the effective Arai decision before host-specific formatting. Also report reasons such as skipped tool or no match. Existing wire formats, including silent allow where mandated, stay host-specific. A decision is distinct from an observation that a host executed an action. The verification result separately identifies host, host version/mode when known, evidence type and observation time.

**Proposed choices for approval with this plan.** Opt into direct evaluation by authoring schema version 2; keep v1 as the existing projection format. Start with block and advisory rules on Bash, Write and Edit. Retain existing audit capture as the upgrade default, with explicit metadata-only capture available. Ship the repo Action for GitHub-hosted Linux first. Host credentials and hosted release operations can be supplied by maintainers. These choices bound the cheaper-model build and can be revised before implementation.

## Reference cases for independent verification

Use this complete v2 document as a behavioral contract for C and D. The Bash input below is a synthetic tool request. Run both the positive and nearby negative controls through the normal matcher, and use only disposable files for native probes.

```toml
[meta]
schema_version = 2

[[rule]]
id = "review-marker"
description = "Demonstrate an exact command policy"
when.tool = ["Bash"]
when.command_pattern = "^echo arai-review-marker$"
then.action = "block"
then.message = "Use the allowed review marker."
severity = "block"

[[rule]]
id = "owned-migration"
description = "The migration generator owns new migration files"
when.tool = ["Write"]
when.path = ["migrations/versions/*.py"]
then.action = "block"
then.message = "Generate the migration first."
severity = "block"
```

|---|---|---|
| Bash command `echo arai-review-marker` | deny | `review-marker` |
| Bash command `echo arai-review-marker-ok` | allow | none |
| Write `migrations/versions/001_sample.py` | deny | `owned-migration` |
