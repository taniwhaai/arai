# Grok Build hook re-verification

**2026-11-09.** Arai 1.1.4 built at `2434bdc` on Ubuntu WSL2. Native
headless and ACP tool calls honored an Arai deny and ran an allowed command
on both tested builds. The prior reference run used
[Grok Build 1.0.0](grok-hooks-reverification-1.0.0.md).

| Build | Source |
| --- | --- |
| `1.0.70 (f50904eaee6c) [stable]` | Existing WSL installation |
| `1.0.77 (50ca579fa996) [alpha]` | Offered by `grok update --check --stable` and installed with `grok update --stable` in a disposable home. The downloaded binary reports `[alpha]`. |

## Native probe setup

A disposable Git repo and separate `HOME`, `GROK_HOME` and `ARAI_BASE_DIR`
isolated hook configuration, trust, and audit. Only the native `.grok/hooks`
registration was exercised. The Claude and Cursor hook files generated by
`arai init` were moved out of the probe repo because Grok also reads those
formats.

```bash
probe=$(mktemp -d)
mkdir -p "$probe/project" "$probe/home" "$probe/grok-home"
export HOME="$probe/home" GROK_HOME="$probe/grok-home"
export ARAI_BASE_DIR="$probe/arai-state" ARAI_TELEMETRY=off
cd "$probe/project"
git init -q
arai init
arai add 'Never run cargo clean'
arai status
mv .claude/settings.json "$probe/claude-settings.json"
mv .cursor/hooks.json "$probe/cursor-hooks.json"
```

Grok used the documented custom-model configuration with
`base_url = "http://127.0.0.1:<port>/v1"`,
`api_backend = "chat_completions"` and a dummy key. The loopback endpoint
returned a streamed `run_terminal_command` call with `command` and
`description` arguments, then a text response after receiving the tool
result. The CLI, hook subprocesses and shell executor were the vendor
binary's own paths. Hosted inference and interactive TUI were outside this
probe. [Custom model configuration](https://docs.x.ai/build/settings).

## Headless and ACP

Each headless call used the following command, substituting the probe command
in the prompt. The untrusted run used a fresh `GROK_HOME` and omitted
`--trust`.

```bash
grok --no-auto-update --trust --always-approve --max-turns 2 \
  -m local-probe --output-format streaming-json \
  -p 'Run this exact harmless shell command once: cargo clean --help > latest-deny-marker'
```

For ACP the runner started
`grok --no-auto-update --trust agent stdio --leader-socket "$GROK_HOME/leader-probe.sock"`.
It sent newline-delimited JSON-RPC requests in order:

```text
initialize    {"protocolVersion":1,"clientCapabilities":{}}
session/new   {"cwd":"<probe project>","mcpServers":[]}
session/prompt {"sessionId":"<returned session id>","prompt":[{"type":"text","text":"Run this exact harmless shell command once: cargo clean --help > latest-acp-deny-marker"}]}
```

The allow probe changed the command to `printf allow > latest-acp-allow-marker`.
The client selected `allow_once` when ACP requested shell permission.
[Headless and ACP reference](https://docs.x.ai/build/cli/headless-scripting).

| Entry point | Observed on 1.0.77 |
| --- | --- |
| Headless without `--trust` | Shell redirection created `latest-untrusted-marker`. Arai's project hook did not fire. |
| Headless with `--trust`, `cargo clean --help > latest-deny-marker` | The tool update had `status: failed` and `Hook denied` with Arai's rule reason. The marker was absent. |
| Headless with `--trust`, `printf allow > latest-allow-marker` | The shell wrote `allow` to the marker. |
| ACP with `--trust`, denied command | `initialize` advertised `pre_tool_use` in `x.ai/hooks.blockingEvents`. `hook_execution` for `project/arai` reported `blocked: true`. The tool update carried Arai's reason and the marker was absent. |
| ACP with `--trust`, allowed command | Arai PreToolUse and PostToolUse reported success. The shell wrote `allow` to the marker. |

The ACP sessions also recorded successful Arai `session_start` and
`user_prompt_submit` runs. `grok --no-auto-update inspect --json` reported
`projectTrusted: true` and all four Arai events. The command
`arai why 'cargo clean --help > latest-deny-marker'` identified the block rule.
Redacted `arai audit --event=PreToolUse --json` excerpts from the two native
denies follow. `arai audit --verify` passed.

```jsonl
{"ts":"2026-11-09T04:08:20Z","event":"PreToolUse","tool":"Bash","decision":"deny","prompt_preview":"cargo clean --help > latest-deny-marker"}
{"ts":"2026-11-09T04:08:22Z","event":"PreToolUse","tool":"Bash","decision":"deny","prompt_preview":"cargo clean --help > latest-acp-deny-marker"}
```

## Payload and registration checks

A command hook recorded stdin and its arguments, then exited successfully.
The same shell call matched all three registration patterns `Bash`, `^Bash$`
and `^run_terminal_command$`. The captured PreToolUse payload carried both
`hookEventName: "pre_tool_use"` and `hook_event_name: "PreToolUse"`.
`toolName` and `tool_name` were both `run_terminal_command`, and both tool
input objects carried the same `command` and `description`.
`GROK_HOOK_EVENT` was `pre_tool_use`. Arai recorded the canonical tool `Bash`.

With the hook script's executable path alone in `command` and
`"args": ["array-sentinel", "two words"]`, the script received two arguments.
A command string with an inline argument also worked by itself. Combining
that shell-form string with `args` did not invoke the script. Arai's
registration uses the working shell form.

A separate `type: "http"` PreToolUse hook POSTed the same event to localhost
and returned `{"decision":"allow"}`. It coexisted with Arai's command hook
and did not override the Arai deny. Grok also documents `SubagentStart` and
`SubagentStop`. This probe did not capture their payloads.
[Grok Build hook configuration](https://docs.x.ai/build/features/hooks).

## Direct Arai replay

Separately from the host runs, the following command returned exit 2 and
`decision: deny` for both event spellings on the blocked command. The
nonmatching command returned exit 0 with empty stdout.

```bash
GROK_HOOK_EVENT=pre_tool_use arai guardrails --match-stdin < payload.json
```

An `arai test` scenario set built from the captured envelope passed 3/3
cases covering the dual spelling, a PascalCase variant and a no-match
control. The [committed dual-field fixture](../../tests/fixtures/grok-pre-tool-use.json)
also passed against the probe's rule store.
